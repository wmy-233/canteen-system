## 1 项目概述

### 1.1 项目背景

校园食堂午餐时段集中，现场排队时间长，学生对菜品余量和取餐进度缺少直观了解，商家备菜主要依赖经验。与此同时，学生将餐食带回宿舍、图书馆等校内地点的需求较为普遍，但缺少规范的校内配送渠道。

本项目围绕上述场景，建设一套覆盖学生点餐、商家出餐、校园配送与后台管理的完整系统，使点餐、支付、核销、配送、反馈和管理形成闭环。

### 1.2 建设目标

- 建成前后端分离的 Java Web 系统，覆盖四类用户角色。
- 实现菜品展示、购物车、订单、钱包、优惠券、取餐码与二维码等完整点餐链路。
- 实现限量菜防超卖、跨档口原子下单、退款全量回滚等交易一致性能力。
- 实现校园配送员抢单、跑腿费担保结算与配送状态流转。
- 实现站内消息、投诉工单、操作日志、统计分析与智能助手等增强功能。
- 完成数据库设计、接口开发、页面实现、测试验证与文档交付。

### 1.3 项目内容

系统由四个业务端组成，各端职责如下：

| 业务端 | 主要内容 |
|---|---|
| 学生端 | 浏览菜品与余量、加入购物车、下单支付、使用优惠券、查看订单、取餐码与二维码、评价、投诉、消息中心、AI 助手 |
| 商家端 | 档口信息管理、菜品增删改查、出餐看板、扫码核销、语音播报、销量统计、投诉回应 |
| 校园配送端 | 抢单大厅、接单、我的配送、标记送达、跑腿费结算 |
| 管理端 | 用户管理、档口审核、配送调度、投诉裁定、优惠券投放、操作日志、经营统计 |

## 3 系统设计

### 3.1 总体架构

系统采用前后端分离架构，前端基于 Vue 3 与 Vite，后端基于 Spring Boot，数据层使用 MySQL 与 MyBatis，缓存与分布式锁使用 Redis/Redisson。

```text
Vue 3 前端
    │  axios /api
    ▼
Spring Security → Controller → Service → MyBatis Mapper → MySQL
                         │
                         ├─ Redis/Redisson：库存预减、热销榜、分布式锁
                         ├─ AOP：操作日志采集与落库
                         └─ 定时任务：投诉超时处理
```

### 3.2 技术选型

| 层次 | 技术 | 说明 |
|---|---|---|
| 前端框架 | Vue 3、Vite 5、Vue Router 4、Pinia | 构建四端页面与路由权限 |
| UI 组件 | Element Plus、ECharts | 后台界面、图表与交互组件 |
| 后端框架 | Java 11、Spring Boot 2.7、Spring MVC | 提供 REST 接口 |
| 安全框架 | Spring Security、JWT、BCrypt | 登录认证、角色鉴权、密码加密 |
| 持久层 | MyBatis、PageHelper | SQL 映射、分页查询 |
| 数据缓存 | Redis、Redisson | 库存预减、热销榜、分布式锁 |
| 数据库 | MySQL 8 | 业务数据持久化 |
| 接口文档 | Knife4j | 接口调试与文档展示 |
| 日志 | Logback、AOP | 文件日志与数据库日志 |

### 3.3 数据库设计

系统共设计 20 张数据表，按业务域划分如下：

| 业务域 | 数据表 | 说明 |
|---|---|---|
| 权限域 | user、role、user_role、menu、role_menu | 用户、角色、用户角色关联、权限菜单与角色菜单关联 |
| 食堂域 | canteen、stall、dish_category、dish | 食堂、档口、菜品分类与菜品信息 |
| 交易域 | cart_item、order_info、order_item、wallet_record | 购物车、订单主表、订单明细与钱包流水 |
| 营销反馈域 | coupon、user_coupon、review | 优惠券、用户领券与菜品评价 |
| 扩展域 | rider、sys_message、complaint、sys_operation_log | 校园配送员、站内消息、投诉工单与操作日志 |

### 3.4 核心流程设计

| 流程 | 设计说明 |
|---|---|
| 防超卖 | Redis 预减库存、Redisson 菜品锁、MySQL 条件更新三重保障 |
| 跨档口下单 | 多个档口商品在一个事务内生成子订单，使用同一批次号统一回滚 |
| 退款回滚 | 退单与投诉退款统一回滚余额、优惠券、库存、销量与缓存数据 |
| 校园配送 | 下单收取跑腿费，配送员接单后流转状态，送达后结算跑腿费 |
| 投诉闭环 | 学生提交、商家回应、管理员裁定，超时工单自动提醒 |
| 操作日志 | 关键操作通过注解自动记录，日志同时写入文件与数据库 |
| 智能助手 | 前端对话组件结合后端接口，支持菜品推荐与订单查询 |

## 4 系统实现

### 4.1 后端实现

后端采用经典分层结构，包含 Controller、Service、Mapper、Entity、DTO、VO、安全、切面与配置等包。核心实现包括：

- 订单服务完成算价、选券、库存校验、下单、退单与核销；
- 事务服务统一处理建单、扣款、流水、券核销、库存变更与退款回滚；
- 配送服务完成骑手管理、抢单、指派、送达与跑腿费结算；
- 投诉服务完成投诉提交、回应、裁定、退款与超时处理；
- 安全模块完成 JWT 解析、用户状态校验、角色加载与接口鉴权；
- 日志切面完成关键操作的文件日志与数据库日志双写；
- Redis 支撑库存预减、热销榜与分布式锁。

### 4.2 前端实现

前端按角色组织页面与路由，使用 Axios 统一调用后端接口，使用 Pinia 保存登录态与角色信息。实现内容包括：

- 四套主题布局与角色菜单；
- 学生端菜品浏览、购物车、结算、订单、钱包、优惠券、评价、投诉与消息页面；
- 商家端菜品管理、出餐看板、扫码核销、语音播报与统计页面；
- 校园配送端抢单大厅、我的配送与送达页面；
- 管理端用户、档口、配送、投诉、优惠券、日志与统计页面；
- 智能助手对话组件与菜品推荐卡片。

### 4.3 数据库与基础设施实现

- 完成 20 张业务表设计与初始化数据脚本；
- 使用 Docker Compose 统一启动 MySQL 与 Redis；
- 完成 RBAC 权限数据、演示账号、食堂档口、菜品、优惠券与配送演示数据；
- 完成接口文档、操作日志、站内消息与文件日志配置；
- 完成项目构建、运行说明与交付文档。

### 4.4 技术特点

- 三重机制保障限量菜不超卖；
- 跨档口批量下单使用单事务保证一致性；
- 退款操作统一回滚订单全部副作用；
- 校园配送采用担保交易模式，跑腿费送达后结算；
- Redis 与 Redisson 提供缓存和并发控制能力；
- 四角色权限隔离，关键操作留痕可查；
- AI 助手增强系统交互体验。
