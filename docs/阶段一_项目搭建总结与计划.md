**不是"一个人全做完下一个人再做"**，而是"关键单点有先后，其余全是并行"。只有 2 个真正卡人的依赖点：

```

        │  ← 接口没好，B 和 C 的联调都做不了，先用各自的方式模拟

        └─→ C：写 init_data.sql 插入演示账号/菜品（依赖表已存在）
```

## 三、注意事项（明确给三人的规矩与坑）

### 通用规矩
1. **禁止直接 push main 分支**；每个人在自己的 feature 分支开发，merge 用 Pull Request
2. commit 信息规范前缀：`feat:` 新功能、`fix:` 修 bug、`docs:` 文档、`sql:` 数据库变更——**数据库表结构一有变动，必须同步改 schema.sql 且在群里说一声**，防止各自本地库结构不一致
3. 每天开工先 `git pull`，收工前 push，避免大冲突
4. 接口路径规范：REST 风格，如 `/api/dish/list`、`/api/order/create`；返回值统一用 `Result` 对象

### 已知的技术坑（踩过的都写在这里）
1. **JDK 版本**：本机是 JDK 25，Spring Boot 2.7 编译可通过但**运行时不受支持**，必须统一装 JDK 11 或 17（IDEA 中 Project SDK 切换即可）
2. **Lombok**：JDK 21+ 必须配置注解处理器（pom 中已配好，勿删该 plugin）
3. **MySQL 密码注意**：application.yml 数据源默认密码 123456，各人本地密码不同就改 yml，**不要把真实密钥改了以后直接提交到仓库**（约定默认值统一为 123456，各自本地一致最简单）
4. **Redis Windows 环境**：统一用 Docker（仓库根目录 `docker-compose.yml`，`docker compose up -d` 即可）；本机装过原生 Redis 服务的必须先停用（`net stop Redis`），否则 6379 端口冲突；Docker Desktop 未启动时后端会**自动降级运行**（登录/下单等主流程不受影响，热销榜等亮点功能不可用）
5. **前端跨域**：Vite 已配置 dev 代理到 8080，写 axios 时 baseURL 用 `/api` 即可，不要写 `http://localhost:8080` 写死

### AI 辅助开发的规矩（全组遵守）
1. AI 生成的代码**必须本地跑通再提交**，禁止复制粘贴未运行的代码
2. 提问 AI 时固定带上：`Spring Boot 2.7.x + JDK 11 + MyBatis + Java` 环境信息，防止版本漂移
3. 三个核心逻辑（防超卖、RBAC、取餐码）每个负责人**必须能脱稿讲原理**（答辩老师会查）
4. **个人学习总结必须自己写**，AI 只能用于文档初稿或润色

## 四、项目架构说明与各文件作用

### 1. 技术架构图（示意）
```
┌──────────────────────────────────┐        ┌──────────────────────────────────┐
│         前端 VUE3 + Vite          │  axios │        后端 Spring Boot 2.7       │
│  Element Plus 组件库              │ ──────>│  Spring Security 权限过滤链       │
│  用户端 / 商家端 / 管理端 三套布局  │  /api  │  └─ Controller 接口层             │
│                                  │ <──────│      └─ Service 业务层            │
│  Pinia：token/角色状态管理         │  JSON  │         ├─ MyBatis Mapper → MySQL │
│  axios：统一携带 token/错误处理    │        │         ├─ Redis（防超卖/ZSet/限流）│
│  ECharts：商家销量图表             │        │         └─ Logback（slf4j 日志）   │
└──────────────────────────────────┘        └──────────────────────────────────┘
```
- 前后端**完全分离**：前端只负责页面与交互，后端只负责业务与数据；通过 REST API + JSON 通信
- 前端开发环境已配置代理：axios 里的 `/api` 请求会自动转发到后端 8080 端口（vite.config.js）

### 2. 后端文件设计（backend/）

| 文件 | 作用 |
|---|---|
| `pom.xml` | 依赖管理：SpringBoot 2.7.18 + Security + Redis + MyBatis + JWT + knife4j（接口文档）+ Redisson（分布式锁）+ Lombok |
| `CanteenApplication.java` | 启动入口 |
| `common/Result.java` | 统一返回体：`{code, message, data}`，所有接口统一用它，前端好统一处理 |
| `common/GlobalExceptionHandler.java` | 全局异常处理：把任何异常转为统一 JSON，前端只显示友好提示 |
| `common/PageResult.java` | 分页返回体（列表页用） |
| `config/SecurityConfig.java` | Spring Security 配置：目前"全部放行"是**骨架期的临时状态**，第 1 周组员 C 会接入 JWT 并写 RBAC 路径规则（TODO 注释已写清） |
| `config/RedisConfig.java` | Redis 的 key 用 String、value 用 JSON 序列化（不用改，直接用） |
| `config/Knife4jConfig.java` | 接口文档自动生成配置，启动后打开 `localhost:8080/doc.html` 人人可看传参文档 |
| `controller/HealthController.java` | 测试接口：访问 `/api/health` 验证后端是否活着 |
| `resources/application.yml` | 总配置：端口 8080、MySQL 账号密码、Redis 地址、JWT 密钥 |
| `resources/logback.xml` | 日志输出的文件规则：按天滚动 + 错误单独文件（满足作业"日志框架"要求） |
| `resources/mapper/` | 后续 MyBatis XML 映射文件目录 |
| `controller/service/mapper/entity/...` 空包 | 后端业务代码开展的分包：controller（接口）/ service（业务）/ mapper（数据库映射）/ entity（数据库实体）/ dto（请求体）/ vo（返回体）/ config（配置）/ common（通用）/ aspect（日志切面）/ interceptor（限流）/ util（工具） |
