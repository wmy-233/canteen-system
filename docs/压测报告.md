# 智慧校园食堂点餐系统 · 防超卖压测报告（C4）

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.0（2026-11-19 实测） |
| 责任人 | 组员 C |
| 对应需求 | FR-STU-06（三重防超卖）/ SRS 第 8.3 节降级口径 |
| 压测对象 | `POST /api/order`（限量菜下单接口） |
| 工具 | `scripts/stress_oversell.mjs`（Node.js 原生 fetch，脚本体见仓库） |

## 1. 测试目标

验证限量菜抢购的硬指标（SRS UC-02）：**初始库存 N，N' 个并发请求每人 1 份 → 成功订单数必须 = N，`dish.daily_stock` 终值 = 0，多一份即超卖、少一份即失败**；并在 Redis 不可用时验证降级路径仍不超卖。

## 2. 环境与方法

- 环境：Docker（MySQL 8 + Redis 6，按现行 main 口径：16 基础表 + 3 个补丁 = 20 表）+ 本机 Spring Boot 后端（登录/下单接口可用）。
- 测试菜品：`dish.id=3`（红烧排骨），`daily_stock=30`。
- 并发模型：脚本一次发出 **50 个并发** `POST /api/order`，items 为 `dishId=3, quantity=1`；每人 1 份，竞争 30 份库存。
- 干扰排除：使用**专用压测账号**（无优惠券），避免学生账号的满减券在并发下抢用导致非预期失败；下单前充值 1000 元保证余额充足。
- 判定标准：`success = 30` 且 `soldOut（"已抢完"类业务错误）= 20` 且 `other = 0`，数据库库存终值 = 0。
- 重置方式：每轮压测前 `docker compose down -v && up`，重打三个补丁，恢复库存 30 与空订单基线。

## 3. 场景一：Redis 正常（三重防超卖全链路）

| 项 | 结果 |
|---|---|
| 并发数 | 50 |
| 初始库存 | 30 |
| 成功订单 | **30** |
| 售罄拒绝 | **20**（均提示"红烧排骨已抢完"） |
| 其他异常 | **0** |
| 耗时 | 1032 ms |
| DB 库存终值 | **0** |
| 压测账号余额 | 520.00（1000 − 30×16，无券无折扣） |
| Redis 预减 key | `dish:stock:3` = 0（与 DB 一致） |
| 结论 | ✅ **通过**：零超卖、零少卖，三重保险（Redis 预减 → Redisson 锁 → MySQL 条件更新）全链路生效 |

## 4. 场景二：Redis 停止（降级路径）

| 项 | 结果 |
|---|---|
| Redis 容器状态 | **已停止**（`docker ps` 无 canteen-redis） |
| 后端状态 | 正常提供服务（`/api/health` = 200） |
| 并发数 / 初始库存 | 50 / 30 |
| 成功订单 | **30** |
| 售罄拒绝 | **20** |
| 其他异常 | **0** |
| 耗时 | 1005 ms |
| DB 库存终值 | **0** |
| 成功单数（DB 核对） | **30** |
| 结论 | ✅ **通过**：Redis 完全不可用时，系统自动降级为纯 MySQL 条件更新（`WHERE daily_stock >= 1`），仍保证零超卖，印证 SRS 8.3 |

## 5. 汇总

| 场景 | 并发 | 库存 | 成功 | 售罄 | 其他 | 库存终值 | 结果 |
|---|---|---|---|---|---|---|---|
| Redis 正常 | 50 | 30 | 30 | 20 | 0 | 0 | ✅ |
| Redis 停止 | 50 | 30 | 30 | 20 | 0 | 0 | ✅ |

**两轮合计 100 个并发请求，成功 60 单、售罄 40 单、异常 0，库存两次都精确归零。**

## 6. 复现步骤

```bash
# 1. 按 README 起环境并打三个补丁，重置到库存 30 的基线
docker compose up -d
docker exec -i canteen-mysql mysql -uroot -p123456 canteen < sql/patch_message_complaint.sql
docker exec -i canteen-mysql mysql -uroot -p123456 canteen < sql/patch_rider.sql
docker exec -i canteen-mysql mysql -uroot -p123456 canteen < sql/patch_enhancements.sql

# 2. 启动后端后执行（默认 50 并发抢 dish=3 的 30 份库存）
node scripts/stress_oversell.mjs

# 3. 降级场景：先 docker stop canteen-redis，再重跑步骤 2（需先重置库存）

# 4. 数据库核对
docker exec canteen-mysql mysql -uroot -p123456 -e "SELECT daily_stock FROM canteen.dish WHERE id=3"
```
